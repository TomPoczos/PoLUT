# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-script generator that produces 172 physically-grounded film-emulation 3D LUTs (`.cube` files) for Kodak Tri-X 400 (B&W), four color reversal (slide) stocks — Fuji Velvia 50, Kodachrome 64, Fuji Provia 100F, Kodak Ektachrome 100D — and six color *negative* stocks — Kodak Portra 400, Kodak Ektar 100, Kodak Gold 200, Kodak Ultramax 400, Fuji Superia Reala, Fuji Superia X-tra 400 — intended to replace a raw processor's tone mapper (AgX/filmic/sigmoid) entirely rather than sit downstream of it. See README.md for the full darkroom/color-science rationale, data provenance, and known limitations — that context is not repeated here.

## Commands

```
python generate_film_looks.py                            # regenerate all 172 LUTs at 65^3
python generate_film_looks.py --size 33                   # smaller/faster grid for iteration
python generate_film_looks.py --only trix                  # regenerate only trix_classic/ + trix_modern/
python generate_film_looks.py --only velvia kodachrome64    # regenerate only velvia/ + kodachrome64/
python generate_film_looks.py --only negative-portra-400     # regenerate only negative-portra-400/
python generate_film_looks.py --colorspace pq2020            # generate against Rec.2020 + PQ instead of Adobe RGB
```

`--only` takes `nargs='+'` over `trix velvia kodachrome64 provia100f ektachrome100d negative-portra-400 negative-ektar-100 negative-gold-200 negative-ultramax-400 negative-superia-reala negative-superia-xtra-400` — any subset, not just one.

`--colorspace` takes `adobergb` (default) or `pq2020`; see "LUT module application color space" below. The committed `.cube` files are all `adobergb` — regenerating with `--colorspace pq2020` produces a parallel set that is not (yet) committed, so don't run it into the tracked output folders without deliberately intending to replace the committed baseline.

No dependencies beyond the Python 3 standard library (`argparse`, `math`, `os`, `time`). No build step, no test suite, no linter configured — the only "check" is running the generator and confirming it completes without error and diffing/regenerating the output `.cube` files.

The generated `.cube` files under `trix_classic/`, `trix_modern/`, `velvia/`, `kodachrome64/`, `provia100f/`, `ektachrome100d/`, `negative-portra-400/`, `negative-ektar-100/`, `negative-gold-200/`, `negative-ultramax-400/`, `negative-superia-reala/`, `negative-superia-xtra-400/` are committed to git as build artifacts, all generated at the default `--colorspace adobergb`. **After changing any film data or algorithm in `generate_film_looks.py`, regenerate all 172 files at the default colorspace and commit them alongside the script change** — don't let the script and the checked-in LUTs drift apart.

## Architecture

Everything lives in `generate_film_looks.py`, structured as one straight pipeline, top to bottom:

1. **Spectral/colorimetric constants** — CIE 1931 2° observer + D65 illuminant tables (`CIE`, `D65`), Adobe RGB primary matrices (`_MA`/`_MA_INV`) and gamma (`_AG`), CIELAB helpers (`_lf`/`_lfi`) feeding `hk_mul()`, the Helmholtz-Kohlrausch exposure-multiplier function (Fairchild & Pirrotta 1991).
2. **Film datasets** — hardcoded digitized curves: `TRIX_SENS`/`TRIX_DEV7` (Kodak Tri-X spectral sensitivity + 7-min dev H&D curve), `POLY` (Polymax Fine-Art paper grades 0–5), `VELVIA_SENS`/`VELVIA_CURVES`, `KODACHROME64_SENS`/`KODACHROME64_CURVES`, `PROVIA100F_SENS`/`PROVIA100F_CURVES`, `EKTACHROME100D_SENS`/`EKTACHROME100D_CURVES` (4 reversal films, 3 independent dye-layer sensitivities + characteristic curves each), `PORTRA400_SENS`/`PORTRA400_CURVES`, `EKTAR100_SENS`/`EKTAR100_CURVES`, `GOLD200_SENS`/`GOLD200_CURVES`, `ULTRAMAX400_SENS`/`ULTRAMAX400_CURVES`, `SUPERIA_REALA_SENS`/`SUPERIA_REALA_CURVES`, `SUPERIA_XTRA400_SENS`/`SUPERIA_XTRA400_CURVES` (6 camera color *negative* stocks, same 3-layer shape — see point 5/7 and the "negative vs. reversal" invariant below for how their cascade differs), `INTERNEGATIVE_II_SENS`/`INTERNEGATIVE_II_CURVES` (EASTMAN Color Internegative II Film 5272/7272 — the duplicating negative every *reversal* film's cascade routes through, digitized via `film_paper_filter_data/tools/curve_digitizer/` from the real datasheet, not from the general `spectral_film_lut` pool), `FILTERS` (Wratten filter spectral transmission %). These are the ground-truth inputs; treat them as data, not something to "clean up" — the one exception is `SUPERIA_XTRA400_SENS` layer 1, which has a single confirmed-bad source sample (a ~1.5-log-unit dive-and-recovery between otherwise-smooth neighbors, not a real spectral feature) dropped at transcription time; see that constant's own comment. All 3-layer datasets share one index convention — `[0]`=red-sensitive/cyan-forming, `[1]`=green-sensitive/magenta-forming, `[2]`=blue-sensitive/yellow-forming — confirmed against each material's raw source JSON before transcribing, not assumed; the `curve_digitizer` tool's own output uses the opposite (blue/green/red) order and must be explicitly reordered when pulled in (see `INTERNEGATIVE_II_SENS`/`INTERNEGATIVE_II_CURVES`'s comment). Portra 400/Ektar 100/Gold 200's curves were independently cross-checked against the real Kodak Alaris publication PDFs (`papers/kodak_portra_400_E-4050.pdf` etc.) — see README "Data provenance" for the method and results.
3. **Print paper ladder** — `CA_SUPER_TYPE_C`, `CA_PRO_PDII`, `PORTRA_ENDURA`, `CA_DPII`, `SUPRA_ENDURA` (5 of the 7 real, legitimate RA-4 papers in `film_paper_filter_data/papers/color/for_negatives/`, 3 layers each; `ENDURA_PREMIER`/Kodak Endura Premier and Fuji Crystal Archive Maxima are real candidates too but currently unused — measured too close to a neighboring rung to add a useful one, see README — so they're left as raw JSON rather than shipped Python constants), assembled into `PAPER_LADDER` (look name → curve) and `COLOR_LOOKS` (the 5-entry look-name ordering). This one ladder is shared by all 10 color films (both `COLOR_FILMS` and `NEGATIVE_FILMS`) — see README "Choosing a print paper" for the selection method (`tools/measure_paper_punch.py`, which measures the real cascade rather than estimating each paper in isolation) and the measured-span table behind the ordering. `tools/measure_paper_punch.py` itself only loops `COLOR_FILMS` (the 4 reversal stocks) — the negative-film span measurement backing the README's "same ladder" claim was checked ad hoc, not via a re-runnable part of that script.
4. **Weight computation** — `_weights()` integrates a sensitivity curve (optionally through a Wratten filter) against D65 and the Adobe RGB primary matrix to get an (R,G,B)→exposure weight triple. Tri-X gets one weight triple per filter; every color film gets one per dye layer via `layer_weights()`.
5. **Cascade builders** — `_find_anchor()` is the shared "find x where curve y crosses a target density" search, used on every stage of a cascade, not just the last (see history below). It scans from index `start` (0 by default — the well-behaved, non-solarized end of the curve for every dataset that doesn't need otherwise), clamps to the nearest endpoint if the target density falls outside the digitized range, and raises if the curve isn't monotonic in the region scanned before the crossing rather than silently picking a wrong segment. `build_print_cascade(stages)` is the general N-stage composer: `stages` is an ordered `[(curve, increasing, start, ref_d), ...]` list, first = what receives scene light, last = the final print material. Every stage but the last is a pure forward evaluation via `_il()` (its density becomes the next stage's printing exposure, calibrated off that stage's own reference exposure — where `_find_anchor()` finds density=`ref_d` — no search needed for the exposure flow itself, only for where to calibrate it); only the last stage is grey-anchored to 18% reflectance instead of `ref_d` (which is ignored for that stage), since that's the one material whose own density has to reproduce exactly 18% reflectance when the whole chain is fed `GREY` scene exposure. `build_trix_cascade(paper)` is a thin 2-stage wrapper (`TRIX_DEV7` → `paper`) kept for its existing call sites. Every `COLOR_FILMS` (reversal) film's cascade is 3-stage: its own reversal curve → `INTERNEGATIVE_II_CURVES` → a `PAPER_LADDER` paper — all four are reversal (slide) stocks, none can go straight onto negative paper the way `build_trix_cascade()`'s 2-stage shape assumes. Every `NEGATIVE_FILMS` film's cascade, by contrast, *is* that 2-stage shape: its own negative curve → a `PAPER_LADDER` paper directly, via `_negative_stage_fn()` (the `NEGATIVE_FILMS`-equivalent of `_reversal_stage_fn()`, `increasing=True` on both stages instead of `False` on the first) — these are genuine camera negatives, so they skip the internegative stage entirely rather than being forced through it. Each stage's `start` index is computed per curve/layer by `_detect_lead_noise_start()` rather than hand-derived — it scans a bounded leading window (15 samples) for a direction violation and returns the index right after the last one found, 0 if none. `PAPER_LADDER`'s Kodak Supra Endura entry auto-detects `start=1` on its blue/yellow-forming layer, because its raw curve has a single leading digitization-noise sample on its Dmin plateau before the real monotonic climb begins — verified the real grey-anchor crossing lands well clear of it regardless of which film it's paired with, since that crossing depends only on the paper's own curve. Restores what the deleted `build_velvia_print_cascade()` used to do automatically, rather than requiring a hand-tuned magic number at every call site (see `tasks/09-hardcoded-anchor-start-index-no-autodetect.md`) — bounded to a small leading window so it can't accidentally "fix" a curve's genuine non-monotonic tail (Polymax grades 0/1 near Dmax, reversal-layer solarization) which must stay visible to `_find_anchor()`'s own monotonicity check.

   **`ref_d` provenance, and a real regression this caught**: an earlier version computed each non-final stage's reference internally as its density-range midpoint, unconditionally. That left a real, measurable stop-plus of highlight headroom unused (verified: shipped `Velvia50_Classic_Normal.cube`'s neutral-white corner topped out at encoded 0.827 instead of the ~0.93-0.94 Tri-X reliably reaches) because two independently-plotted manufacturer datasheets have no reason to share an exposure-range midpoint. Fixed by moving `ref_d` out to the caller so each one can be justified individually: `INTERNEGATIVE_II_LAD_AIM[li]` for the internegative stage (Kodak's own published "Internegative LAD Aim" density, TI1301 sec.9 — real data, and it happened to sit within ~3% of the density-midpoint it replaced, so keeping it was a pure upgrade). For each reversal film's own stage, `reversal_grey_target()` (the real 18%-reflectance grey convention) was tried next and made headroom measurably *worse* — checked directly: on Velvia's own curve that target sits at only ~20-23% of the layer's density range, versus 50% for `density_midpoint()`, because "where does grey belong" and "how do I not waste this stage's dynamic range in a calibration handoff" are different questions, and real published LAD data only answers the first one for this transition. `density_midpoint()` (the density-midpoint of the curve's own straight-line portion, excluding toe/shoulder — `_straight_line_density_range()` finds it by resampling onto a uniform exposure grid and keeping the widest contiguous run within 50% of peak local slope, since raw point-to-point slope on this file's unevenly-spaced digitized points spikes on short intervals from ordinary noise) is used there instead. Not a fabricated number — the material's own real measured response — but not a published aim density either, clearly commented as a fallback rather than presented as manufacturer data. It does, however, match Kodak's own stated *general* LAD methodology for duplicating films with no per-film published aim: "the specified aims are at the center of the usable straight-line portion of the sensitometric curve" (EASTMAN EKTACHROME Film 5240/7240 datasheet TI0986 sec.11) — found by searching for that film's own data specifically (see `reversal_grey_target()`'s docstring for why that search happened), and worth citing precisely because it means this fallback isn't arbitrary, it's an approximation of Kodak's own documented practice for exactly this situation. Same function, same citation, used for `TRIX_DEV7` in `build_trix_cascade()` too (no published aim density exists for it either, but it was independently verified, not assumed, to already land within rounding of the theoretical best case on both ends for every Polymax grade before this refinement, and stayed within ~0.003 of that after it).
6. **LUT writers** — `write_bw_lut()` combines color→exposure via **geometric mean** (`R^wr * G^wg * B^wb`, i.e. log-density-space mixing — physically correct for how film responds to light, and only valid on linear scene-referred data) with optional HK correction, then the Tri-X cascade, writing an achromatic `.cube`. `write_color_lut()` computes each color film's dye-layer exposure via **arithmetic** weighted sum instead (each layer responds to a narrow spectral band, so geometric cross-channel suppression doesn't apply), then applies each layer's own cascade transfer function to produce RGB output. Shared by all 10 color films (`COLOR_FILMS` and `NEGATIVE_FILMS` alike), not Velvia-specific despite the name.
7. **`main()`** — parses `--size`/`--output`/`--only` (`nargs='+'` over `trix` + the 4 `COLOR_FILM_KEYS` + the 6 `NEGATIVE_FILM_KEYS`), iterates the classic (no HK) vs modern (HK) variant × filter × look combinations for Tri-X into `trix_classic/`/`trix_modern/`, then for each color film in `COLOR_FILMS` iterates variant × `COLOR_LOOKS` (5 real-paper looks, no filter dimension) into one folder per film (`velvia/`, `kodachrome64/`, `provia100f/`, `ektachrome100d/`) with Classic/Modern folded into the filename instead of a separate folder, then a second, separate loop over `NEGATIVE_FILMS` doing the same thing into `negative-<film>/` folders (`negative-portra-400/`, `negative-ektar-100/`, `negative-gold-200/`, `negative-ultramax-400/`, `negative-superia-reala/`, `negative-superia-xtra-400/`) — see "File naming" invariant below for why the split isn't symmetric with Tri-X, and the negative-vs-reversal invariant below for why `NEGATIVE_FILMS` is a second loop rather than folded into the `COLOR_FILMS` one.

Key invariants to preserve when editing:
- Input/output color space is always Adobe RGB (gamma-encoded in the `.cube`, decoded to linear internally via `adec`/`aenc`). This is deliberate (see README "Why Adobe RGB") — don't switch to sRGB primaries.
- Geometric mean for Tri-X/B&W, arithmetic mean for every color film's per-layer exposure — these are not interchangeable; the README's "Density-space geometric mean" section explains why each is physically correct for its case.
- Every color film in `COLOR_FILMS` is a reversal (slide) stock and routes through `INTERNEGATIVE_II_CURVES`, by design — this project's color-film architecture exists specifically to exercise the internegative-duplication cascade. Color *negative* film (Kodak Portra 400, Ektar 100, Gold 200, Ultramax 400; Fuji Superia Reala, Superia X-tra 400) lives in the separate `NEGATIVE_FILMS` list instead: negatives print straight onto paper with a 2-stage cascade (the same shape `build_trix_cascade()` uses, generalized via `_negative_stage_fn()`) and never touch `INTERNEGATIVE_II_CURVES` at all, so they don't belong in `COLOR_FILMS` alongside films that do. An earlier version of this project folded three of these same films into `COLOR_FILMS` and removed them for exactly that reason; don't repeat that mistake if extending either lineup — a new reversal film goes in `COLOR_FILMS` via `_reversal_stage_fn()`, a new camera negative goes in `NEGATIVE_FILMS` via `_negative_stage_fn()`, never the other list.
- `GREY = 0.18` is the anchor point every transfer function is normalized around; `build_print_cascade()` grey-anchors its *last* stage to 18% reflectance specifically, and every other stage to its own `ref_d` via the same `_find_anchor()` machinery (see point 5) — every stage's calibration point search requires monotonicity up to that crossing, not just the final one, so a leading/trailing wobble anywhere in a cascade (not only in a final-stage paper) can now raise if it sits before the relevant target. Several digitized curves are non-monotonic near their tails (Polymax grades 0/1 dip near Dmax; every reversal film's dye layers solarize past their minimum density; `SUPRA_ENDURA` has a single leading Dmin-plateau wobble on one layer; `PROVIA100F_CURVES` layers 0 and 2 have a leading Dmax-plateau wobble, which is why `_detect_lead_noise_start()` auto-detects `start=1` for those two layers even though it's a non-final stage — layer 1 is clean and auto-detects to `start=0`) — harmless in every currently-shipped case because the relevant target density sits well before the wobble `_find_anchor()` would actually scan into, but check any new/edited curve data against whichever `ref_d`/grey-target it'll actually be searched for, not just against 18% reflectance.
- Reference densities (`ref_d`) are never computed unconditionally inside `build_print_cascade()` — each caller supplies one, explicitly, so its provenance (real published data vs. labeled fallback) is visible at the call site rather than hidden in a shared default. Before adding a new stage type, check whether a real published calibration number exists for it first (the way `INTERNEGATIVE_II_LAD_AIM` does for the internegative); don't assume the "more real-sounding" number is automatically the right one for *this specific* calibration question, either — `reversal_grey_target()` (18% reflectance, a completely real and universal photographic convention) was tried as a reversal film's own `ref_d` and made highlight headroom measurably worse than the plain `density_midpoint()` fallback, because it answers "where does grey belong," not "how do I avoid wasting this stage's dynamic range in a calibration handoff" — a different question that happened to have no better published answer. Real data has to answer the right question, not just be real.
- Don't cascade a reversal film's own curve directly through a print paper whose own gamma is much above ~1.3 without an intermediate low-contrast stage: system gamma is the product of every stage's local gamma (real sensitometry), and a reversal film's native curve is already gamma ≈1.5–1.9 (Velvia ≈1.63, Kodachrome 64 ≈1.84, Provia 100F ≈1.48, Ektachrome 100D ≈1.76). This is *why* every color film's cascade routes through `INTERNEGATIVE_II_CURVES` (γ≈0.527) before any paper — the internegative's low gamma is what makes the rest of `PAPER_LADDER` (paper γ 1.8–2.45) safe to compound, landing every film's full look range at system γ roughly 1.4–2.4 instead of the ~2.7–4.5 a direct reversal-film→paper cascade through the same papers would produce. Ilfochrome Micrographic M/P (gamma 1.5–2.1) was tried as a *direct* (no internegative) paper for Velvia and rejected — compounds to 2.0–3.0, verified to clip skin/sky highlights within ~1 stop of grey. Don't reintroduce a direct reversal-to-paper cascade for any reversal film without either an internegative-equivalent stage or re-deriving this bound.
- `HK_MAX_MUL = 3.0` bounds `hk_mul()`'s exposure multiplier. The Fairchild & Pirrotta (1991) HK formula has no built-in ceiling and was only validated against real Munsell chips (`C*` roughly 6–87); wide-gamut Adobe RGB scene data can reach `C* ≈ 136` and would otherwise extrapolate into 6–7× multipliers on saturated shadows/midtones. See README "Helmholtz-Kohlrausch correction" for how 3.0 was derived from the paper's own measured data. Don't remove or raise this clamp without re-deriving it against the source data.
- File/folder naming (`TriX_<Filter>_<Look>.cube` in `trix_classic/`/`trix_modern/`; `<FilePrefix>_<Classic|Modern>_<Look>.cube` in one folder per color film, e.g. `Velvia50_Classic_Normal.cube` in `velvia/`, `Portra400_Classic_Normal.cube` in `negative-portra-400/`) and the `LOOKS`/`COLOR_LOOKS`/`FILTER_ORDER` orderings are consumed by nothing else in-repo, but changing them changes the committed output filenames — coordinate with README's file listing if you do. The two naming schemes are intentionally asymmetric: Tri-X splits classic/modern into separate folders because each variant already holds 36 files (6 looks × 6 filters); color films (reversal and negative alike) have no filter dimension (10 files per variant pair), not enough to justify a folder split, so Classic/Modern goes in the filename instead — not an oversight, don't "fix" one to match the other without re-reading this. `NEGATIVE_FILMS` folders use a flat `negative-<film-name>/` prefix (e.g. `negative-ektar-100/`) rather than a `negative/<film-name>/` parent directory — deliberately, to keep the top-level folder listing flat instead of adding another directory level for six films; don't restructure into a subfolder without a reason beyond symmetry with how `COLOR_FILMS` folders are named.
