# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-script generator that produces 196 physically-grounded film-emulation 3D LUTs (`.cube` files) for Kodak Tri-X 400 (B&W), four color reversal (slide) stocks — Fuji Velvia 50, Kodachrome 64, Fuji Provia 100F, Kodak Ektachrome 100D — and six color *negative* stocks — Kodak Portra 400, Kodak Ektar 100, Kodak Gold 200, Kodak Ultramax 400, Fuji Superia Reala, Fuji Superia X-tra 400 — intended to replace a raw processor's tone mapper (AgX/filmic/sigmoid) entirely rather than sit downstream of it. Each reversal stock ships two independent print routes (5 internegative-route looks + 3 gamma-corrected direct-print-route looks, see point 5b below and README "Why a reversal print crushes without correction"). See README.md for the full darkroom/color-science rationale, data provenance, and known limitations — that context is not repeated here.

## Commands

```
python generate_film_looks.py                            # regenerate all 196 LUTs at 65^3
python generate_film_looks.py --size 33                   # smaller/faster grid for iteration
python generate_film_looks.py --only trix                  # regenerate only trix_classic/ + trix_modern/
python generate_film_looks.py --only velvia kodachrome64    # regenerate only velvia/ + kodachrome64/
python generate_film_looks.py --only negative-portra-400     # regenerate only negative-portra-400/
python generate_film_looks.py --colorspace pq2020            # generate against Rec.2020 + PQ instead of Adobe RGB
python generate_film_looks.py --gamma 1.5                    # override the Jones system-gamma target (default 1.35)
```

`--only` takes `nargs='+'` over `trix velvia kodachrome64 provia100f ektachrome100d negative-portra-400 negative-ektar-100 negative-gold-200 negative-ultramax-400 negative-superia-reala negative-superia-xtra-400` — any subset, not just one. Each of the 4 reversal-film keys generates *both* of that film's print routes (16 LUTs) into its one folder; there's no separate `--only` key for "direct-print looks only."

`--colorspace` takes `adobergb` (default) or `pq2020`; see "LUT module application color space" below. The committed `.cube` files are all `adobergb` — regenerating with `--colorspace pq2020` produces a parallel set that is not (yet) committed, so don't run it into the tracked output folders without deliberately intending to replace the committed baseline.

`--gamma` overrides `GAMMA_CORRECT_TARGET` (default 1.35, see that constant's own comment block for the full citation trail) for the direct-print and negative-film gamma correction — a real, physically-cited quantity (Jones's system-gamma target, tuned per real-world use within the cited light-surround-to-dark-surround range of ~1.1-1.6), not an arbitrary knob, so it's exposed as a CLI switch rather than requiring a code edit to experiment with. The committed `.cube` files are all generated at the default; regenerating with `--gamma` produces a parallel set that isn't committed unless you're deliberately replacing the baseline, same caveat as `--colorspace`.

`generate_film_looks.py` itself has no *code* dependencies beyond the Python 3 standard library (`argparse`, `math`, `os`, `time`, `json`) — this is deliberate and preserved even though `tools/gamma_correction_fit/` and `tools/spectral_upsample_fit/` (both separate `uv`-managed offline tools, scipy/numpy, same pattern as `film_paper_filter_data/tools/curve_digitizer/`) now exist: those tools *produce* data generate_film_looks.py only ever consumes, they aren't imported by or run as part of generation. `tools/gamma_correction_fit/` produces the `*_SPLITGAUSS_FIT` constants transcribed directly into this file; `tools/spectral_upsample_fit/` produces `spectral_upsampling_tables/<colorspace>.json` (see point 4b), the one exception to "everything is a plain Python constant in this file" — that table is loaded at generation time via stdlib `json`, the first time this file has ever read an external data file rather than embedding everything as a literal. No build step, no test suite, no linter configured for the main generator — the only "check" is running it and confirming it completes without error and diffing/regenerating the output `.cube` files.

The generated `.cube` files under `trix_classic/`, `trix_modern/`, `velvia/`, `kodachrome64/`, `provia100f/`, `ektachrome100d/`, `negative-portra-400/`, `negative-ektar-100/`, `negative-gold-200/`, `negative-ultramax-400/`, `negative-superia-reala/`, `negative-superia-xtra-400/`, and `spectral_upsampling_tables/adobergb.json`/`pq2020.json`, are all committed to git as build artifacts, generated/fit at the default `--colorspace adobergb` (and the `pq2020` table alongside it, since both are needed for `--colorspace pq2020` to work at all — see point 4b). **After changing any film data or algorithm in `generate_film_looks.py`, regenerate all 196 files at the default colorspace and commit them alongside the script change** — don't let the script and the checked-in LUTs drift apart. The `spectral_upsampling_tables/*.json` files only need re-fitting (`uv run tools/spectral_upsample_fit/main.py`) if the CIE/D65 tables or a colour space's primary matrix ever change — they don't depend on any film's own sensitivity/curve data, so an ordinary film-data edit doesn't require re-running that tool.

## Architecture

Everything lives in `generate_film_looks.py`, structured as one straight pipeline, top to bottom:

1. **Spectral/colorimetric constants** — CIE 1931 2° observer + D65 illuminant tables (`CIE`, `D65`), Adobe RGB primary matrices (`_MA`/`_MA_INV`) and gamma (`_AG`), CIELAB helpers (`_lf`/`_lfi`) feeding `hk_mul()`, the Helmholtz-Kohlrausch exposure-multiplier function (Fairchild & Pirrotta 1991).
2. **Film datasets** — hardcoded digitized curves: `TRIX_SENS`/`TRIX_DEV7` (Kodak Tri-X spectral sensitivity + 7-min dev H&D curve), `POLY` (Polymax Fine-Art paper grades 0–5), `VELVIA_SENS`/`VELVIA_CURVES`, `KODACHROME64_SENS`/`KODACHROME64_CURVES`, `PROVIA100F_SENS`/`PROVIA100F_CURVES`, `EKTACHROME100D_SENS`/`EKTACHROME100D_CURVES` (4 reversal films, 3 independent dye-layer sensitivities + characteristic curves each), `PORTRA400_SENS`/`PORTRA400_CURVES`, `EKTAR100_SENS`/`EKTAR100_CURVES`, `GOLD200_SENS`/`GOLD200_CURVES`, `ULTRAMAX400_SENS`/`ULTRAMAX400_CURVES`, `SUPERIA_REALA_SENS`/`SUPERIA_REALA_CURVES`, `SUPERIA_XTRA400_SENS`/`SUPERIA_XTRA400_CURVES` (6 camera color *negative* stocks, same 3-layer shape — see point 5/7 and the "negative vs. reversal" invariant below for how their cascade differs), `INTERNEGATIVE_II_SENS`/`INTERNEGATIVE_II_CURVES` (EASTMAN Color Internegative II Film 5272/7272 — the duplicating negative every *reversal* film's internegative-route cascade routes through, digitized via `film_paper_filter_data/tools/curve_digitizer/` from the real datasheet, not from the general `spectral_film_lut` pool), `RADIANCE_III_CURVES`/`ILFOCHROME_M_CURVES`/`ILFOCHROME_P_CURVES` (3 real direct-print papers for reversal originals — no internegative — from `film_paper_filter_data/papers/color/for_reversal/*.json`; curves only, no `_SENS` counterpart, same as every `PAPER_LADDER` paper, since a paper never receives scene light directly — see point 3b), `FILTERS` (Wratten filter spectral transmission %). These are the ground-truth inputs; treat them as data, not something to "clean up" — the one exception is `SUPERIA_XTRA400_SENS` layer 1, which has a single confirmed-bad source sample (a ~1.5-log-unit dive-and-recovery between otherwise-smooth neighbors, not a real spectral feature) dropped at transcription time; see that constant's own comment. All 3-layer datasets share one index convention — `[0]`=red-sensitive/cyan-forming, `[1]`=green-sensitive/magenta-forming, `[2]`=blue-sensitive/yellow-forming — confirmed against each material's raw source JSON before transcribing, not assumed; the `curve_digitizer` tool's own output uses the opposite (blue/green/red) order and must be explicitly reordered when pulled in (see `INTERNEGATIVE_II_SENS`/`INTERNEGATIVE_II_CURVES`'s comment). Portra 400/Ektar 100/Gold 200's curves were independently cross-checked against the real Kodak Alaris publication PDFs (`papers/kodak_portra_400_E-4050.pdf` etc.) — see README "Data provenance" for the method and results.
3. **Print paper ladder** — `CA_SUPER_TYPE_C`, `CA_PRO_PDII`, `PORTRA_ENDURA`, `CA_DPII`, `SUPRA_ENDURA` (5 of the 7 real, legitimate RA-4 papers in `film_paper_filter_data/papers/color/for_negatives/`, 3 layers each; `ENDURA_PREMIER`/Kodak Endura Premier and Fuji Crystal Archive Maxima are real candidates too but currently unused — measured too close to a neighboring rung to add a useful one, see README — so they're left as raw JSON rather than shipped Python constants), assembled into `PAPER_LADDER` (look name → curve) and `COLOR_LOOKS` (the 5-entry look-name ordering). This one ladder is shared by all 10 color films (both `COLOR_FILMS` and `NEGATIVE_FILMS`) — see README "Choosing a print paper" for the selection method (`tools/measure_paper_punch.py`, which measures the real cascade rather than estimating each paper in isolation) and the measured-span table behind the ordering. `tools/measure_paper_punch.py` itself only loops `COLOR_FILMS` (the 4 reversal stocks) — the negative-film span measurement backing the README's "same ladder" claim was checked ad hoc, not via a re-runnable part of that script.
3b. **Direct-print paper ladder** — `DIRECT_PRINT_PAPERS` (name → curve) and `DIRECT_PRINT_LOOKS` (the 3-entry ordering `RadianceIII`, `IlfochromeM`, `IlfochromeP`), the direct-print equivalent of point 3's `PAPER_LADDER`/`COLOR_LOOKS`, used only by the 4 reversal films (`COLOR_FILM_KEYS`), never by `NEGATIVE_FILMS`. Density *falls* with exposure for all three (`increasing=False`), unlike every `PAPER_LADDER` paper (`increasing=True`) — confirmed against each raw JSON, not assumed: these are reversal-process print materials (R-3-family chromogenic reversal paper / dye-destruction), a different animal from RA-4 despite both being "the paper a print comes out on."
4. **Weight computation** — `_weights()` integrates a sensitivity curve (optionally through a Wratten filter) against D65 and the Adobe RGB primary matrix to get an (R,G,B)→exposure weight triple. Tri-X gets one weight triple per filter via `_weights()`, unchanged. Every color film used to get one fixed weight triple per dye layer via `layer_weights()` (since removed) — see point 4b for what replaced it for `COLOR_FILMS`/`NEGATIVE_FILMS` and why; B&W is unaffected (no per-channel colour to get wrong the same way, see `tasks/16-fixed-rgb-weights-no-spectral-reconstruction.md`'s own scope note).

4b. **Per-pixel spectral reconstruction for color films (Jakob & Hanika 2019)** — `layer_weights()`'s fixed `(w_R, w_G, w_B)` triple made every pixel's per-layer exposure a plain `R·w_R + G·w_G + B·w_B` dot product, mathematically equivalent to assuming every photographed colour is exactly a linear-light mixture of the three RGB primaries' own spectral power distributions. Real reflectance spectra aren't that, and a real film's spectral sensitivity isn't colorimetric, so two real colours that are metamers under the CIE 1931 observer (same RGB triple) can and do expose real film differently — a fixed-weight model can't represent that by construction. `build_spectrum_grid()` now reconstructs a real, physically-plausible reflectance spectrum per LUT grid point instead — Jakob, W., & Hanika, J. (2019), "A Low-Dimensional Function Space for Efficient Spectral Upsampling," *Computer Graphics Forum* 38(2), 147-155 (`papers/spectral_upsampling/`) — via `_rgb_to_sigmoid_coeffs()` (largest-channel-relative trilinear interpolation into a baked coefficient table) and `_sigmoid_spectrum()` (the closed-form model, `R(λ)=1/2+U/(2√(1+U²))`, `U=c0·λ²+c1·λ+c2`). `layer_exposure_grid()` (the `layer_weights()` replacement) integrates each layer's own real sensitivity curve against that reconstructed spectrum × D65, normalized by the layer's own `Σsens·D65` total so an achromatic grey pixel (whose reconstructed spectrum is exactly flat — a closed-form special case, not interpolated) still yields exposure == the grey value itself, preserving every existing `GREY=0.18` cascade-anchor calibration unchanged. The reconstructed spectrum depends only on the LUT grid coordinate and target colour space, not on which film — `get_spectrum_grid()` caches it once per `(size, colorspace)` and every color film's `layer_exposure_grid()` call in `main()` reuses it, the same "compute once, reuse many" principle as DONE-05/DONE-08/DONE-11. The coefficient table itself is fit offline by `tools/spectral_upsample_fit/` (`uv`-managed, wraps `colour-science`'s independently-tested port of the same paper) against this project's own CIE/D65/primary-matrix data — not `colour-science`'s bundled datasets, so the fit is self-consistent with what this file integrates at runtime — and baked to `spectral_upsampling_tables/<colorspace>.json`; see that tool's own README and `papers/spectral_upsampling/README.md` for the reference implementations studied (the paper authors' own C++ `rgb2spec`, and `colour-science`'s Python port) before choosing this design. `generate_film_looks.py` only ever evaluates that table (stdlib `json` + arithmetic), never re-fits it.
5. **Cascade builders** — `_find_anchor()` is the shared "find x where curve y crosses a target density" search, used on every stage of a cascade, not just the last (see history below). It scans from index `start` (0 by default — the well-behaved, non-solarized end of the curve for every dataset that doesn't need otherwise), clamps to the nearest endpoint if the target density falls outside the digitized range, and raises if the curve isn't monotonic in the region scanned before the crossing rather than silently picking a wrong segment. `build_print_cascade(stages)` is the general N-stage composer: `stages` is an ordered `[(curve, increasing, start, ref_d), ...]` list, first = what receives scene light, last = the final print material. Every stage but the last is a pure forward evaluation via `_il()` (its density becomes the next stage's printing exposure, calibrated off that stage's own reference exposure — where `_find_anchor()` finds density=`ref_d` — no search needed for the exposure flow itself, only for where to calibrate it); only the last stage is grey-anchored to 18% reflectance instead of `ref_d` (which is ignored for that stage), since that's the one material whose own density has to reproduce exactly 18% reflectance when the whole chain is fed `GREY` scene exposure. `build_trix_cascade(paper)` is a thin 2-stage wrapper (`TRIX_DEV7` → `paper`) kept for its existing call sites. Every `COLOR_FILMS` (reversal) film's internegative-route cascade is 3-stage: its own reversal curve → `INTERNEGATIVE_II_CURVES` → a `PAPER_LADDER` paper. Every `NEGATIVE_FILMS` film's cascade is 2-stage: its own negative curve, gamma-corrected (see point 5b) → a `PAPER_LADDER` paper directly, via `_negative_gammacorrect_stage_fn()` (the `NEGATIVE_FILMS`-equivalent of `_reversal_stage_fn()`, `increasing=True` on both stages instead of `False` on the first) — these are genuine camera negatives, so they skip the internegative stage entirely rather than being forced through it. Every `COLOR_FILMS` film's *direct-print*-route cascade is also 2-stage — its own reversal curve, gamma-corrected (see point 5b), → a `DIRECT_PRINT_PAPERS` paper directly, via `_direct_print_stage_fn()`, `increasing=False` on both stages (unlike `_negative_gammacorrect_stage_fn()`'s `True`/`True`, since both a reversal dye layer and a reversal-process print paper have density falling with exposure). Each stage's `start` index is computed per curve/layer by `_detect_lead_noise_start()` rather than hand-derived — it scans a bounded leading window (15 samples) for a direction violation and returns the index right after the last one found, 0 if none. `PAPER_LADDER`'s Kodak Supra Endura entry auto-detects `start=1` on its blue/yellow-forming layer, because its raw curve has a single leading digitization-noise sample on its Dmin plateau before the real monotonic climb begins — verified the real grey-anchor crossing lands well clear of it regardless of which film it's paired with, since that crossing depends only on the paper's own curve. Restores what the deleted `build_velvia_print_cascade()` used to do automatically, rather than requiring a hand-tuned magic number at every call site (see `tasks/09-hardcoded-anchor-start-index-no-autodetect.md`) — bounded to a small leading window so it can't accidentally "fix" a curve's genuine non-monotonic tail (Polymax grades 0/1 near Dmax, reversal-layer solarization) which must stay visible to `_find_anchor()`'s own monotonicity check.

5b. **Gamma correction for the direct-print route** — full physics and history (v1-v4) documented in `generate_film_looks.py`'s own `GAMMA_CORRECT_TARGET` comment block and README "Why a reversal print crushes without correction"; summary here is of the *current* (v4) mechanism only.

    `GAMMA_CORRECT_TARGET` defaults to 1.35, overridable via `--gamma` (not Jones's pure-fidelity 1.0, and not the 1.1 light-surround/reflection-print figure this project targeted initially — Bartleson & Breneman, "Brightness perception in complex fields," *J. Opt. Soc. Am.* 57, 953-957, 1967; full text not accessible, cited via two real secondary sources saved locally, `papers/masking_research/choi_bartleson_breneman_brightness_stevens_power_law.pdf` and `.../roufs_global_brightness_contrast_perceptual_image_quality.pdf`). This project's actual output is a `.cube` LUT that replaces a raw processor's tone mapper and is viewed on a self-luminous monitor, not a physical reflection print hung under room light — the reflection-print figure was the wrong viewing condition, caught by real-world use rendering flat/washed-out. Roufs et al.'s own test rig (a slide scanner feeding a monitor — almost exactly this project's output path) measured "the gamma of the slide scanner - monitor chain was about 1.2 in all cases," optimal effective gamma 1.2-1.3, "very near what Bartleson and Breneman found for TV in 1967" (i.e. the self-luminous-display figure, not the reflection-print one). The target moved to 1.25 (the midpoint of that range) first, then to a 1.35 default after real-world use showed even 1.25 short of expected punch — still inside the cited light-surround-to-dark-surround range (~1.1-1.6) but past the narrow TV midpoint, exposed as `--gamma` rather than hand-tuned again as a fixed constant a fourth time. `gamma_correct_curve()`'s `target` parameter defaults to `None` and falls back to reading the *current* value of the `GAMMA_CORRECT_TARGET` module global at call time (not a stale value captured when the function was defined) — `main()` reassigns the global from `args.gamma` before building any LUT, so this must stay a live lookup, not a def-time-bound default, or `--gamma` would silently do nothing. Two earlier mechanisms at the (then-1.1) target were tried and rejected before v4: a uniform scalar across the whole curve (over-flattened the toe/shoulder, measurably undershot the paper's real Dmax) and a windowed rescale (`_straight_line_window()`-scoped, better but left an arbitrary threshold and local gamma near grey running 20-40% hot vs. the window-*average* target).

    v4 fits a real model to each material's own digitized curve instead of rescaling or discarding its shape: `VELVIA_SPLITGAUSS_FIT`/`KODACHROME64_SPLITGAUSS_FIT`/`PROVIA100F_SPLITGAUSS_FIT`/`EKTACHROME100D_SPLITGAUSS_FIT` (reversal films) and `RADIANCEIII_SPLITGAUSS_FIT`/`ILFOCHROMEM_SPLITGAUSS_FIT`/`ILFOCHROMEP_SPLITGAUSS_FIT` (via `DIRECT_PRINT_PAPER_FIT`) are `(x0, d_lo, d_hi, sigma_lo, sigma_hi)` tuples per layer — an asymmetric cumulative-Gaussian ("split-normal" CDF) fit by `tools/gamma_correction_fit/` (separate `uv`-managed tool, scipy/numpy; see its own README) against the real curve data already in this file, R² > 0.998 on all 21 layers fit. The model is physically motivated, not chosen for convenience: an emulsion's toe/straight-line/shoulder shape is the cumulative distribution of individual grain sensitivities crossing their own exposure threshold (J.H. Webb, *J. Opt. Soc. Am.* 29, 314-326, 1939 — paywalled, cited via corroborating evidence only, see `papers/masking_research/README.md`), and a threshold-crossing process over a log-normal population is standardly idealized as a cumulative Gaussian; asymmetric because toe (grain-threshold statistics) and shoulder (dye/silver exhaustion) are different physical mechanisms with no reason to share a width.

    `_norm_cdf()`/`_norm_pdf()` reimplement the standard normal CDF/PDF with `math.erf` (stdlib only — verified to match `scipy.stats.norm` to float precision, so this file needs no scipy at generation time even though the fit that produced the constants did). `_split_gauss_density()`/`_split_gauss_local_gamma()` evaluate the fitted model and its exact analytic derivative at a point (no window-average, no finite-difference approximation). `gamma_correct_curve(film_params, pivot_x, pivot_d, downstream_gamma, target)` rescales the fitted film model's exposure axis *only* (every fitted density value kept exactly as computed — the model's own real fitted Dmin/Dmax are reached, not truncated) around `(pivot_x, pivot_d)` by whatever factor `k` makes `_split_gauss_local_gamma(film_params, pivot_x) * k == target / downstream_gamma`; since a pure horizontal rescale can't change relative shape, toe:shoulder proportions are preserved exactly. Samples the result to a 61-point dict for `build_print_cascade()`'s existing machinery; construction guarantees monotonicity, so `start=0` is always correct (`_detect_lead_noise_start()` doesn't need to run on it).

    `_direct_print_stage_fn()` computes `na0` (pivot exposure) and `lhg` (the paper's own real grey-reproduction exposure) via `_find_anchor()` on the *original* digitized curves exactly as `build_print_cascade()` itself would, then evaluates `downstream_gamma = _split_gauss_local_gamma(paper_fit[li], lhg)` — the specific paper layer's own fitted gamma at its own real operating point, not a blended or window-averaged number — before building the corrected film curve. Its `stage_fn` now takes `(li, paper, paper_fit)`, not `(li, paper)` — every call site (`main()`) passes `DIRECT_PRINT_PAPER_FIT[look]` alongside `DIRECT_PRINT_PAPERS[look]`.

    Verified (Kodachrome 64 x Radiance III): print's shadow density reaches 2.519 against the fitted model's own real Dmax of 2.561 (0.04 short). Checked across all 4 reversal films x 3 direct-print papers x 3 layers: shortfall under 0.06 density units in every case, local gamma near grey consistently close to `GAMMA_CORRECT_TARGET` with no window-boundary kink. Inserting a second real duplicating material (e.g. EASTMAN Fine Grain Duplicating Panchromatic Negative 2234/5234, `papers/kodak_finegrain_duplicating_pan_2234_TI0147.pdf`) as an intermediate stage was considered and rejected in an earlier round: it is itself a duplicating stock calibrated around some assumed low-contrast "master positive" input, so using it would relocate the exact mismatch this correction exists to escape, not fix it (same failure mode as `INTERNEGATIVE_II_CURVES` against a real reversal original, see above).

    **Extended to `NEGATIVE_FILMS` after real-world use exposed a punch-ordering inversion**: negative-film LUTs (never audited against Jones's rule — see the old, uncorrected `_negative_stage_fn()` this replaced) were rendering punchier than the freshly gamma-corrected reversal films, backwards from the real photographic hierarchy where reversal stock is the punchier material. Measured directly, `PORTRA400_SPLITGAUSS_FIT`/`EKTAR100_SPLITGAUSS_FIT`/`GOLD200_SPLITGAUSS_FIT`/`ULTRAMAX400_SPLITGAUSS_FIT`/`SUPERIA_REALA_SPLITGAUSS_FIT`/`SUPERIA_XTRA400_SPLITGAUSS_FIT` (all 6 negative films) confirmed each film's own native gamma is correctly low (0.47-0.68, the standard negative-stock design so it prints near unity contrast on normally-graded paper) — the mismatch was on the paper side: `EXTRASOFT_LADDER_SPLITGAUSS_FIT`/`SOFT_LADDER_SPLITGAUSS_FIT`/`NORMAL_LADDER_SPLITGAUSS_FIT`/`PUNCHY_LADDER_SPLITGAUSS_FIT`/`EXTRAPUNCHY_LADDER_SPLITGAUSS_FIT` (via `PAPER_LADDER_FIT`) showed `PAPER_LADDER`'s own real gammas run steep (2.5-4.3 on every one of its 5 papers, including "ExtraSoft") and had never been checked against Jones's rule — the ladder's ordering came from measuring rendered *span* (`tools/measure_paper_punch.py`), a different question. `_negative_gammacorrect_stage_fn()` (replacing `_negative_stage_fn()`) applies the identical mechanism as `_direct_print_stage_fn()` — same `gamma_correct_curve()`, same `GAMMA_CORRECT_TARGET`, `increasing=True` on both stages instead of `False`. Verified at the default `GAMMA_CORRECT_TARGET = 1.35`: Portra 400 x Normal paper now runs local gamma ≈1.08-1.46 near grey (was ≈1.4-1.7 uncorrected).

   **`ref_d` provenance, and a real regression this caught**: an earlier version computed each non-final stage's reference internally as its density-range midpoint, unconditionally. That left a real, measurable stop-plus of highlight headroom unused (verified: shipped `Velvia50_Classic_Normal.cube`'s neutral-white corner topped out at encoded 0.827 instead of the ~0.93-0.94 Tri-X reliably reaches) because two independently-plotted manufacturer datasheets have no reason to share an exposure-range midpoint. Fixed by moving `ref_d` out to the caller so each one can be justified individually: `INTERNEGATIVE_II_LAD_AIM[li]` for the internegative stage (Kodak's own published "Internegative LAD Aim" density, TI1301 sec.9 — real data, and it happened to sit within ~3% of the density-midpoint it replaced, so keeping it was a pure upgrade). For each reversal film's own stage, `reversal_grey_target()` (the real 18%-reflectance grey convention) was tried next and made headroom measurably *worse* — checked directly: on Velvia's own curve that target sits at only ~20-23% of the layer's density range, versus 50% for `density_midpoint()`, because "where does grey belong" and "how do I not waste this stage's dynamic range in a calibration handoff" are different questions, and real published LAD data only answers the first one for this transition. `density_midpoint()` (the density-midpoint of the curve's own straight-line portion, excluding toe/shoulder — `_straight_line_density_range()` finds it by resampling onto a uniform exposure grid and keeping the widest contiguous run within 50% of peak local slope, since raw point-to-point slope on this file's unevenly-spaced digitized points spikes on short intervals from ordinary noise) is used there instead. Not a fabricated number — the material's own real measured response — but not a published aim density either, clearly commented as a fallback rather than presented as manufacturer data. It does, however, match Kodak's own stated *general* LAD methodology for duplicating films with no per-film published aim: "the specified aims are at the center of the usable straight-line portion of the sensitometric curve" (EASTMAN EKTACHROME Film 5240/7240 datasheet TI0986 sec.11) — found by searching for that film's own data specifically (see `reversal_grey_target()`'s docstring for why that search happened), and worth citing precisely because it means this fallback isn't arbitrary, it's an approximation of Kodak's own documented practice for exactly this situation. Same function, same citation, used for `TRIX_DEV7` in `build_trix_cascade()` too (no published aim density exists for it either, but it was independently verified, not assumed, to already land within rounding of the theoretical best case on both ends for every Polymax grade before this refinement, and stayed within ~0.003 of that after it).
6. **LUT writers** — `write_bw_lut()` combines color→exposure via **geometric mean** (`R^wr * G^wg * B^wb`, i.e. log-density-space mixing — physically correct for how film responds to light, and only valid on linear scene-referred data) with optional HK correction, then the Tri-X cascade, writing an achromatic `.cube`. `write_color_lut()` takes each color film's dye-layer exposure from a precomputed **per-grid-point exposure grid** (`layer_exposure_grid()`, point 4b — each layer still combines its own reconstructed-spectrum-derived exposure arithmetically, not geometrically, since each layer responds to a narrow spectral band where geometric cross-channel suppression doesn't apply; only *how* that per-pixel exposure number is derived from RGB changed), looked up by the same `(bi,gi,ri)`-nested index its own grid loop already walks, then applies each layer's own cascade transfer function to produce RGB output. Shared by all 10 color films (`COLOR_FILMS` and `NEGATIVE_FILMS` alike), not Velvia-specific despite the name.
7. **`main()`** — parses `--size`/`--output`/`--only` (`nargs='+'` over `trix` + the 4 `COLOR_FILM_KEYS` + the 6 `NEGATIVE_FILM_KEYS`), iterates the classic (no HK) vs modern (HK) variant × filter × look combinations for Tri-X into `trix_classic/`/`trix_modern/`, then for each color film in `COLOR_FILMS` iterates variant × `COLOR_LOOKS` (5 internegative-route real-paper looks, no filter dimension) into one folder per film (`velvia/`, `kodachrome64/`, `provia100f/`, `ektachrome100d/`), *then, in the same per-film loop body, right after*, iterates variant × `DIRECT_PRINT_LOOKS` (3 gamma-corrected direct-print-route looks) into that same folder using `DIRECT_PRINT_STAGE_FNS[key]` — both routes share one folder and one `Classic`/`Modern`-in-filename convention, so a film's 16 files (8 looks × 2 variants) sort together alphabetically. Then a second, separate loop over `NEGATIVE_FILMS` doing the PAPER_LADDER/COLOR_LOOKS thing (no direct-print route — see the invariants below for why) into `negative-<film>/` folders (`negative-portra-400/`, `negative-ektar-100/`, `negative-gold-200/`, `negative-ultramax-400/`, `negative-superia-reala/`, `negative-superia-xtra-400/`) — see "File naming" invariant below for why the split isn't symmetric with Tri-X, and the negative-vs-reversal invariant below for why `NEGATIVE_FILMS` is a second loop rather than folded into the `COLOR_FILMS` one.

Key invariants to preserve when editing:
- Input/output color space is always Adobe RGB (gamma-encoded in the `.cube`, decoded to linear internally via `adec`/`aenc`). This is deliberate (see README "Why Adobe RGB") — don't switch to sRGB primaries.
- Geometric mean for Tri-X/B&W, arithmetic mean for every color film's per-layer exposure — these are not interchangeable; the README's "Density-space geometric mean" section explains why each is physically correct for its case.
- Every color film in `COLOR_FILMS` is a reversal (slide) stock and its internegative-route cascade routes through `INTERNEGATIVE_II_CURVES`, by design — this project's color-film architecture exists specifically to exercise the internegative-duplication cascade, and `_reversal_stage_fn()`/`COLOR_FILMS` are left exactly as they were when the direct-print route was added (see GAMMA_CORRECT_TARGET's block: the internegative route has the identical underlying gamma-product problem, just via a different pairing, and fixing it is separate, not-yet-done work — don't assume it's already fixed because the direct-print route is). Color *negative* film (Kodak Portra 400, Ektar 100, Gold 200, Ultramax 400; Fuji Superia Reala, Superia X-tra 400) lives in the separate `NEGATIVE_FILMS` list instead: negatives print straight onto paper with a 2-stage cascade (the same shape `build_trix_cascade()` uses, generalized via `_negative_gammacorrect_stage_fn()`) and never touch `INTERNEGATIVE_II_CURVES` at all, so they don't belong in `COLOR_FILMS` alongside films that do, and they don't get a `DIRECT_PRINT_PAPERS` route either (they already print onto real paper directly, that's what negative film is for). They *do* get the same gamma correction the reversal direct-print route gets, though — added after real-world use showed negative films rendering punchier than the freshly-corrected reversal films, backwards from the real hierarchy; a camera negative's own native gamma is correctly low (0.47-0.68), but `PAPER_LADDER`'s own real gammas (2.5-4.3) are steep enough that the pairing still overshot `GAMMA_CORRECT_TARGET`, uncorrected — see point 5b. An earlier version of this project folded three of these same films into `COLOR_FILMS` and removed them for exactly that reason; don't repeat that mistake if extending either lineup — a new reversal film goes in `COLOR_FILMS` via `_reversal_stage_fn()` (and, if it should also get a direct-print route, `DIRECT_PRINT_STAGE_FNS` via `_direct_print_stage_fn()`), a new camera negative goes in `NEGATIVE_FILMS` via `_negative_gammacorrect_stage_fn()`, never the other list.
- `GREY = 0.18` is the anchor point every transfer function is normalized around; `build_print_cascade()` grey-anchors its *last* stage to 18% reflectance specifically, and every other stage to its own `ref_d` via the same `_find_anchor()` machinery (see point 5) — every stage's calibration point search requires monotonicity up to that crossing, not just the final one, so a leading/trailing wobble anywhere in a cascade (not only in a final-stage paper) can now raise if it sits before the relevant target. Several digitized curves are non-monotonic near their tails (Polymax grades 0/1 dip near Dmax; every reversal film's dye layers solarize past their minimum density; `SUPRA_ENDURA` has a single leading Dmin-plateau wobble on one layer; `PROVIA100F_CURVES` layers 0 and 2 have a leading Dmax-plateau wobble, which is why `_detect_lead_noise_start()` auto-detects `start=1` for those two layers even though it's a non-final stage — layer 1 is clean and auto-detects to `start=0`) — harmless in every currently-shipped case because the relevant target density sits well before the wobble `_find_anchor()` would actually scan into, but check any new/edited curve data against whichever `ref_d`/grey-target it'll actually be searched for, not just against 18% reflectance.
- Reference densities (`ref_d`) are never computed unconditionally inside `build_print_cascade()` — each caller supplies one, explicitly, so its provenance (real published data vs. labeled fallback) is visible at the call site rather than hidden in a shared default. Before adding a new stage type, check whether a real published calibration number exists for it first (the way `INTERNEGATIVE_II_LAD_AIM` does for the internegative); don't assume the "more real-sounding" number is automatically the right one for *this specific* calibration question, either — `reversal_grey_target()` (18% reflectance, a completely real and universal photographic convention) was tried as a reversal film's own `ref_d` and made highlight headroom measurably worse than the plain `density_midpoint()` fallback, because it answers "where does grey belong," not "how do I avoid wasting this stage's dynamic range in a calibration handoff" — a different question that happened to have no better published answer. Real data has to answer the right question, not just be real.
- System gamma is the product of every stage's own local gamma (real sensitometry, L.A. Jones 1920 — see GAMMA_CORRECT_TARGET's block), and a reversal film's native curve is already gamma ≈1.4–2.1 per layer (measured via `_measured_gamma()`). `PAPER_LADDER`'s own real gammas run steeper than either reversal film's or negative film's own native gamma alone would suggest is safe — 2.5–4.3 per layer, measured the same way, on every one of its 5 papers including "ExtraSoft" — which is why *both* `DIRECT_PRINT_PAPERS` (reversal) and `PAPER_LADDER` (negative) pairings need an explicit correction rather than trusting either material's low-gamma reputation alone. Three ways this project keeps that from overshooting a print's usable range: `COLOR_FILMS`'s internegative route puts `INTERNEGATIVE_II_CURVES` (γ≈0.527) between the reversal curve and any `PAPER_LADDER` paper — still uncorrected/unaudited as of this writing, see below; `DIRECT_PRINT_PAPERS`'s direct-print route gamma-corrects the reversal curve itself (`gamma_correct_curve()`) against the specific direct-print paper's own fitted gamma, targeting system γ = `GAMMA_CORRECT_TARGET` (default 1.35, overridable via `--gamma` — see point 5b — not Jones's pure-fidelity 1.0, and not the reflection-print figure of 1.1 this project targeted before real-world use showed it too flat); `NEGATIVE_FILMS` gamma-corrects the negative curve itself the same way, against `PAPER_LADDER`. **Do not cascade a reversal or negative film's own *uncorrected* curve directly through any print paper of real gamma** — that's exactly the crush (reversal) and punch-inversion (negative) this project measured and fixed (README "Why a reversal print crushes without correction"), and exactly why the *old*, deleted `build_velvia_print_cascade()` (direct, uncorrected, onto Radiance III) and an earlier attempt at Ilfochrome Micrographic M/P (also direct, uncorrected) both compounded to an unusably contrasty result and were replaced/rejected at the time. Both papers are used again now, on purpose, specifically *with* the correction — don't read their presence in `DIRECT_PRINT_PAPERS` as a reversal of that old rejection; the rejection was of the uncorrected pairing, which no longer exists in this codebase. If extending `DIRECT_PRINT_PAPERS` or `PAPER_LADDER` with a new paper, or `COLOR_FILMS`/`NEGATIVE_FILMS` with a new film, re-run `tools/gamma_correction_fit/` (`uv run main.py`) to fit and transcribe a new `*_SPLITGAUSS_FIT` entry for the new material's real digitized curve rather than assuming a number from memory or reusing another material's fit.
- `HK_MAX_MUL = 3.0` bounds `hk_mul()`'s exposure multiplier. The Fairchild & Pirrotta (1991) HK formula has no built-in ceiling and was only validated against real Munsell chips (`C*` roughly 6–87); wide-gamut Adobe RGB scene data can reach `C* ≈ 136` and would otherwise extrapolate into 6–7× multipliers on saturated shadows/midtones. See README "Helmholtz-Kohlrausch correction" for how 3.0 was derived from the paper's own measured data. Don't remove or raise this clamp without re-deriving it against the source data.
- File/folder naming (`TriX_<Filter>_<Look>.cube` in `trix_classic/`/`trix_modern/`; `<FilePrefix>_<Classic|Modern>_<Look>.cube` in one folder per color film, e.g. `Velvia50_Classic_Normal.cube` and `Velvia50_Classic_RadianceIII.cube` both in `velvia/`, `Portra400_Classic_Normal.cube` in `negative-portra-400/`) and the `LOOKS`/`COLOR_LOOKS`/`DIRECT_PRINT_LOOKS`/`FILTER_ORDER` orderings are consumed by nothing else in-repo, but changing them changes the committed output filenames — coordinate with README's file listing if you do. The two naming schemes are intentionally asymmetric: Tri-X splits classic/modern into separate folders because each variant already holds 36 files (6 looks × 6 filters); color negative films have no filter dimension (10 files per variant pair) and reversal films have 16 (8 looks × 2 variants, `COLOR_LOOKS` + `DIRECT_PRINT_LOOKS` both landing in the same folder) — neither is enough to justify a folder split, so Classic/Modern goes in the filename instead — not an oversight, don't "fix" one to match the other without re-reading this. `NEGATIVE_FILMS` folders use a flat `negative-<film-name>/` prefix (e.g. `negative-ektar-100/`) rather than a `negative/<film-name>/` parent directory — deliberately, to keep the top-level folder listing flat instead of adding another directory level for six films; don't restructure into a subfolder without a reason beyond symmetry with how `COLOR_FILMS` folders are named. `DIRECT_PRINT_LOOKS` names (`RadianceIII`, `IlfochromeM`, `IlfochromeP`) deliberately don't collide with any `COLOR_LOOKS` name, so both look sets can share one folder/filename convention unambiguously.
